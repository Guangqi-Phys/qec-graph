# 从下游数据需求倒推的本地编译准备计划

状态：计划，尚未实现或验收。日期：2026-11-16。

依据：[Human.md](../../design/Human.md)、[DESIGN §4–5](../../design/DESIGN.md#4-data-contracts)、[§9](../../design/DESIGN.md#9-human-view)、[§16](../../design/DESIGN.md#16-searchable-knowledge-and-implementation-roadmap)。本文件提出后续工作，不改写当前已实现契约。

## 1. 先定义准备完成后需要什么

目标是给后续程序和模型一份**完整、按原文结构组织、保留数学与实验条件、引用可解析、能回到原始来源的材料包**。准备阶段不回答科学问题，不填充研究记录，不生成九问答案。

“之后容易提取”应当意味着：

1. 下游不必重新解压、猜入口、补宏包、猜引用编号或把多文件正文拼起来。
2. 可以先读目录，再定位小片段，继续展开所在段落、章节、附录和相关图表。
3. 公式、表格、引用、条件说明没有在转成纯文本时丢失。
4. 展开的可读文本和原始引文分开，引用证据能绑定正确论文版本和原始字节。
5. 未解析、歧义、缺资源、未参与编译的内容可被下游看见；不以空结果表示原文不存在。

这不是“准备好一批 `[n,k,d]`、LER、噪声参数或思想总结”。那些是后续独立抽取阶段的产物。

## 2. Human.md 中的科学产出需要哪些输入

| 后续需要提取的知识 | 准备层必须交付的原文材料和结构 | 不能提前作出的判断 |
| --- | --- | --- |
| 基本假设、定义、定理、证明 | 连续段落；作者已声明的环境名称、标题、编号和标签；公式；所在节；前后文 | 定理成立、假设已齐全、证明有效、引用构成证明依赖 |
| 码族、数学构造、具体码实例 | 构造步骤、算法、公式、参数表、矩阵及附件；索引、基、bit order、X/Z 等约定原文 | 参数相同就是同一码；构造自动产生已验证实例 |
| rate、distance 与界 | 公式和上下标；比较符号；描述 exact/lower/upper/interval 的完整句子；脚注和适用条件 | 将上界当下界；将模拟或启发式结果当精确距离 |
| syndrome extraction 电路 | 图形资产、电路 TeX/TikZ 源码、图注、标签、正文引用、调度与 rounds/depth 定义 | 图中每条线的语义、code distance 等于 circuit distance |
| error model、idle/loss 等机制 | 方法和附录中的段落、概率公式、参数表、脚注、相关图注 | 未提到某个噪声项就表示该项不存在 |
| decoder 原理与比较 | 算法/伪代码、复杂度说明、设置、版本、运行条件、比较表和曲线说明 | 文中相邻结果属于同一实验；软件名称等于确定版本 |
| fidelity、LER、真实实验表现 | 表格结构及单位、曲线与图例、坐标轴、图注、数据附件、shots/discards/不确定性/筛选口径的原文 | 从图像自动臆造精确数据点；自动判断跨实验可比 |

表格不能只留一串数：需要保留表题、行列标题、多级表头、合并单元格、单位、脚注和正文中的解释。图不能只留图注：还要保留原始图文件、图例、坐标轴可读性和正文关联。只有图像的曲线可以保留图像并注明尚无机器数据；准备阶段不执行数字化估点。

## 3. 九问需要什么上下文

| Human.md 的问题 | 必须能取到的材料 |
| --- | --- |
| 1. 想解决什么问题 | 摘要、引言中的问题陈述、相关定义和完整段落 |
| 2. 为什么重要 | 引言动机、背景、前人工作及对应文献 |
| 3. 解决了吗，如何解决 | 方法、算法、主要结果、局限与结论；不能只给摘要 |
| 4. 用了什么直觉、想法 | 作者明确表达直觉的段落、示意图、例子及前后文；未表达的留未知 |
| 5. 重要假设 | 全局设置、局部条件、定理前提、实验方法、脚注和附录 |
| 6. 结论及与前人成果关系 | 结论、比较语句、适用范围、相关引用和文献条目 |
| 7. 遗留问题、后续提问 | 讨论、局限、展望、开放问题、正文中的限定语句 |
| 8. 反直觉发现 | 作者相关表达、对应结果、图表及条件；不由准备层判断“反直觉” |
| 9. 有趣的支线结论 | remarks、examples、附录、补充材料和非主线段落 |

上述位置是下游阅读的入口提示，不是只保留这些章节的白名单。正文、附录和补充材料必须完整保留。准备层不推断九类标签，也不把“这次没有提取到”改写为“论文没有”。

## 4. 最小交付合同

沿用项目受管理快照、原始来源和现有文档模型，避免另建一套领域数据库。下列是逻辑数据要求；新格式实现时必须版本化并提供兼容适配，不将计划中的字段宣称为当前 schema。

| 数据 | 最少保留什么 | 用途 |
| --- | --- | --- |
| 来源与身份 | 原始包、原始成员字节、包/文件 SHA-256、已注册 paper/version；包名、入口及各文档作用 | 固定来源，防止混版本；包名只作线索，不决定对象身份 |
| 文档骨架 | 标题作者的原始写法及可读值、摘要、节/子节、段落、列表、附录、脚注；父子关系和原文阅读顺序 | 目录导航、小块定位、连续章节阅读 |
| 数学与作者声明的环境 | inline/display math、原始 TeX、编号/标签、环境原名/声明标题、定理和证明文字的原有边界 | 后续识别数学内容；不猜正文的科学类型 |
| 图表、算法与资产 | 原始图/矩阵/数据/电路资源，图注表注，表格行列与合并关系，算法顺序、标签、正文关联 | 保留数据解释所需的结构和条件 |
| 引用与目标 | 原文引用位置、原始调用、展开后的 key、refsection/refcontext、目标 ID/编号/显示文字、文献条目文本；DOI/arXiv 只保存确实存在的值 | 自定义 cite 宏、BibTeX/Biber、局部编号均可消歧 |
| 上下文连接 | 文档/章节路径、相邻段落、作者的交叉引用、图表和文献关联、可获取的宏定义 | 为下游 `get_context` 提供结构线索，不推断完整数学依赖 |
| 来源映射 | 原始文件及哈希、原始字节范围、明确编码后的 codepoint 半开范围、1-based 行号；派生内容自己的坐标；映射精度和角色 | 校验原文引句、解释宏展开、避免混用 PDF/行号/字符偏移 |
| 完整性与限制 | 输入/输出文件清单，参与编译的根和依赖，未参与内容，缺失资源，未解析结构、歧义引用、opaque 内容及原因 | 让后续选择可用内容，阻止静默遗漏 |

同一内容至少可区分三种读取方式：**原始字节**、**规范化结构**、**派生阅读文本**。后两者都不能冒充原始引文。数学 TeX 应保留；MathML 可以作为附加表示，不要求所有公式先转成 MathML 才允许保存原文。

一个小片段的基本能力示意（不是现行 schema）：

```text
片段 ID / 论文版本 / 所在节 / 父节点 / 前后顺序
原始片段定位（可为多个 source span）
可读表示 + 数学/图表/引用标记
子节点、作者原有交叉引用、相关图注/文献的可解析句柄
转换方式、源映射精度、未解析项
```

不预先给片段填 `quantum_code`、`lower_bound`、`noise_model`、九问类别或证明依赖。这些需要后续研究抽取与独立校验。

## 5. 编译能提供什么，不能替代什么

本地编译是准备流水线的第一项计算工作；在它之前只做归档、校验、安全解包、入口/构建配置选择，不先做静态正文准备，也不先调用 AI。

| 工具/产物 | 提供的帮助 | 仍不能保证的事情 |
| --- | --- | --- |
| 原生 TeX 编译 | 执行宏、条件与计数器，使用实际引擎和宏包，形成一个具体构建视图 | 不输出通用的完整语义 AST，不自动证明原文全部分支已经保留 |
| `.aux` / `.toc` 等 | 作者编号、交叉引用、实际 citation key、目录等构建观测 | 不能替代正文，也不能单凭目录重建段落和表格 |
| `.bbl` + `.bib`，必要时 `.bcf` | 保留文献来源字段与实际排版文献；分节/分上下文识别引用 | 不自动补出原文缺失的 DOI、题名、数据库字段；不同来源值仍需保留 |
| `.fls`、构建日志与工具清单 | 实际输入/输出和依赖，环境错误，版本与复现信息 | 不保证未参与这次编译的附件没有研究价值 |
| PDF + SyncTeX | 视觉核对、页面定位和辅助源文件/行定位 | PDF 不保留完整作者结构；SyncTeX 不保证每段展开文本到原始字节的精确映射 |
| 结构转换器 | 尝试形成章节、段落、数学、图表、引用的机器可读标记 | 必须单独验收；不能以“原生 PDF 能编译”推断转换成功 |

HTML/MathML 不被定为唯一必需产物。上一轮 45/47 可编译、8/47 转换基本成功，已经说明应该先固定上述数据合同，再选择能满足合同的转换方式。转换器通常需要处理同一原始工程，不能把“从生成 PDF 转出全部作者结构”作为实现假设。

编译时被条件排除、在 `\end{document}` 后、未链接的附录/补充文件和非正文注释仍保留在原始工程。它们不自动进入当前阅读顺序；分别标注 inactive/uncompiled/unknown，必要时作为单独文档处理。独立论文根不能为了消除入口歧义而合并。

## 6. 模块职责

| 模块职责 | 输入 → 输出 | 禁止承担的事 |
| --- | --- | --- |
| 构建执行器 | 原始工程 + 明确配置 → 编译产物、依赖清单、构建观测、失败日志 | 不分类科学内容，不调用模型，不发布研究记录，不修改归档 |
| 格式转换适配器 | 同一工程 + 构建观测 → 保留作者结构的统一输入表示、引用/资产表、映射和限制 | 不总结、删减、补写或推断科学字段；不将转换损失当成功 |
| preparation | 校验并封装转换结果 → 有版本的受管理材料包及能力状态 | 不回答九问、不生成领域记录、不把模糊映射改成精确映射 |
| 下游结构 parser / 验证器 | 材料包 → 可检索结构和准确来源；检查消费能力 | 不与 preparation 混成一个函数；格式兼容要显式处理 |
| 后续研究抽取 | 已验收的材料及其上下文 → 科研/九问提议 | 不属于本计划；模型提议仍保留真实状态 |

编译/转换是可替换的后端，后续抽取只面向统一合同。准备工具不导入科学抽取 skill；`init` 和读取请求不运行编译器。格式转换适配器与 parser 都可能读取语法，但前者负责保留格式，后者负责消费与校验，避免维护两份科学分类逻辑。

AI 格式修复不进入首轮实现。只有确定的转换失败、明确局部输入和可机械验证的目标格式出现时，才另立任务：指定允许改动、必须保留的字节/标记、映射要求、失败退出条件。该任务也不能填写研究字段或九问；无法保证内容保真就保持 partial。API key 不构成上传许可。

## 7. 逐步实施及停止条件

### 第一步：固定合同与小样验收表

- 输入：本需求对照、已有 47 包清单和现行 parser 接口。
- 动作：为全文顺序、附录、公式、表格、图注、脚注、作者环境、宏引用、BibTeX、Biblatex 分节引用、来源映射各选真实小样；从原文独立标出预期位置与原始字节，固定为金标，不能用转换结果自己充当金标。
- 输出：需求—样例—断言对应表；材料包版本/兼容方案；每项必需/可选能力定义。
- 完成：每一项要求有明确的消费方式和失败状态。科学领域值和九问答案没有进入准备合同。

### 第二步：把已有编译实验收敛成独立执行器

- 输入：未重写的原始包、入口和引擎/依赖配置。
- 动作：复用已经有效的引擎选择、已有 BBL 保留、正确 jobname、历史宏包与缓存隔离；记录配置来源。限制联网、目录读写、运行时间和输出大小。
- 输出：构建 manifest、依赖版本/哈希、PDF、实际产生并与该任务有关的 AUX/BBL/BCF/FLS/SyncTeX 和诊断。没有的产物记录 not_applicable/failed，不能伪造空文件。
- 完成：同样 47 包可复跑；修复或明确保留两篇旧环境失败；首次入口自动发现仍需独立评测，不能把之前确认的入口成绩算成自动能力。

### 第三步：先打通引用和文献格式

- 输入：构建实际使用的 AUX、BBL、BCF、原始 BIB 和来源信息。
- 动作：经典 BibTeX 与 Biblatex 分开适配；保存 key、分节/上下文、显示编号/文字和条目文本。正确识别控制 key、重复/缺失 key 和不同 sorting datalist。引用发生位置不能只靠 AUX 推断，要由正文转换标记/来源证据补全。
- 输出：统一文献与引用表示；来源为 original/derived 的区分；歧义和缺失列表。
- 完成：真实自定义 cite 宏、隐式 BBL、外部 BIB、Biblatex 分节的固定小样通过；每次引用可回到正文与条目，原文自身缺项明确失败或 unknown，不靠 AI 补齐。

### 第四步：打通正文结构转换

- 输入：同一份原始工程、构建配置与第三步引用表示。
- 动作：先验证现有 TeX4ht 路线；按第一步缺项判断是否需要另一转换后端。逐项保存第 4 节合同中的作者结构、TeX 数学和资产。对无法解析的结构保留原始 payload 并报告 opaque，禁止只丢掉报错节点。
- 输出：机器可消费的结构表示和可读视图；各节点映射；原文覆盖/遗漏报告。
- 完成：真实小样的正文及附录顺序、公式、表格、图注、脚注、算法没有遗漏或结构破坏；满足后才冻结主格式和适配器。不能因某工具偏好就先决定全库唯一 HTML/MathML。

### 第五步：来源绑定与 preparation 交付

- 输入：格式转换结果、原始成员字节和依赖/资产清单。
- 动作：逐节点区分精确复制、可验证格式变换、宏展开的多来源映射、仅页/行提示、无法映射；保留调用点与宏定义来源。稳定 ID 绑定原始版本和确定性定位，不靠 PDF 页码或显示编号决定身份。
- 输出：沿用受管理 manifest/文档表示/映射的一个版本化材料包；能力状态与诊断。派生文件哈希与原始包哈希分别保存，验证失败不发布并保留旧产物。
- 完成：用于引证的片段能逐字校验原始来源；近似映射不进入精确引用接口；正文、引用、资产分别有状态，下游实际 parser 能消费合同。

### 第六步：验证“后续提取是否真的更容易”

- 输入：冻结的 47 包、独立小样金标、相同下游 parser，及真实数据库固定 machine 副本。
- 动作：先做零模型检查：获取目录、连续章节、带公式的段落、表格及脚注、图注及资产、引用及文献、附录、精确原文切片。比较当前路线与新路线，记录缺失组件和仍需的特殊处理。新合同需要 parser 适配时单独记录影响，不能混报为准备质量提升。
- 输出：同输入的前后数量、每项结构/映射准确性、失败论文、工具版本、耗时/磁盘、未验收项；实际消费测试和 machine release 身份。
- 完成：必需能力在固定样本通过，无静默丢失、错版本或伪精确定位。machine schema 不兼容先修评测适配或明确未验收，不能修改原库绕过。九问/领域抽取的模型质量和人工评审在后续阶段独立进行。

## 8. 准备阶段的完成判据

全篇 `ready_for_extraction` 必须同时满足：

1. **来源完整**：原始包和成员字节可验证，论文版本清楚，文档/附件的纳入与排除有清单。
2. **可消费**：下游消费程序实际成功读取材料包；有 PDF 或有 HTML 文件不算。
3. **结构保留**：正文及适用的附录、公式、表格、图注、脚注、算法、作者环境能完整读取、按原顺序展开。未支持的必需节点会阻止全篇 ready。
4. **引用可追**：适用的内部引用和文献引用保留调用位置、目标与歧义；原文自身错误也明示，不能用统计总数掩盖单个缺口。
5. **来源可信**：被标为精确的 source span 字节/字符校验全部通过；编译展开和可读文本没有被当成原始引文。
6. **限制透明**：未知与不适用明确；mandatory 项无未说明遗漏。局部可用以 partial 和具体覆盖范围交付，不升级为全篇完成。

编译失败、转换失败、准备失败、下游解析失败分别报告；科研问题缺少答案是后续覆盖状态，不是准备程序应补写内容的理由。

最先实施的是**统一数据合同、小样金标、编译执行器、文献/引用适配**；然后扩展正文转换与来源映射，最后决定是否切换默认准备路径。现有兼容路径在新合同验收前保留，但不放到新编译路径之前执行，也不静默替代失败结果。
