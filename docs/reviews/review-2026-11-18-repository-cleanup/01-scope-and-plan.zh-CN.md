# 仓库重整评审与实施计划

日期 2026-11-18。基线为 `886a1e8`。本轮按现行接口和数据契约整理整个仓库，
删除专供旧版 QEC Graph 的入口、读取分支与自动迁移。功能验收覆盖材料准备和提取、
单论文图与切片、工作区发布、查询、MCP、人类九问视图、可选 AI 和发布包装。

## 已确认的基线

- 启用真实 TeX 的全量套件通过 639 项，Ruff 与复杂度检查通过。
- `tools/reproduce.py` 端到端报告覆盖 4 个源文件、29 个片段、36 个节点、99 条边、
  11 条搜索命中和 16 个上下文节点。
- 材料准备与离线提取的现行契约分别是 `qecgraph.prepare/3` 的
  `compile-prepare-v20` 和 `qecgraph.prepared_extraction/1`。固定语料、留出集及
  源文件、引用和投影的验证结果已有可复查工件。
  [提取交接评审](../review-2026-11-18-prepared-extraction/01-contract-gap-and-rollout.zh-CN.md)

## 发现与分批实施

| 批次 | 现状 | 改动及验收 |
| --- | --- | --- |
| 1. 准备模块归位 | `tools/prepare_arxiv.py` 及其解析器、格式规划适配器和技能实现旧静态材料路线。v20 仍从旧模块借用输入加载与日志式发布。 | 将当前源包读取归入准备入口，材料写入与恢复归入发布模块。删除静态格式与专有测试，迁移共享的来源保真和故障恢复测试。原生编译、隔离、老论文输入与 v20 产物继续实测。 |
| 2. 固定材料合同 | 读取端保留 v19 环境声明双判据、旧文档边界和规范化映射例外。回放工具也接受旧记录缺少本次物料绑定。 | 读取与回放绑定当前 v20 合同、实际 receipt 和源证据。用 47 份固定材料及 6 份留出材料复核，并验证旧版或篡改工件被明确拒绝。 |
| 3. 入口与读服务 | 部分命令平铺别名、Python 转接模块与 MCP 文档中的兼容说法重复了实际功能。 | 指定公开命令与模块所有者，移除纯转接和废弃别名。保留目前用于日常工作的短命令、独立切片器、只读图工具及 MCP 当代通用客户端接口。覆盖打包、帮助、CLI 和 MCP 实际调用。 |
| 4. 数据、AI 和渲染 | 语义技能运行与验证仍按旧技能版本分支。人类视图内嵌旧布局删除逻辑，读取端有若干旧快照回退。 | 现行 schema 各有单一验证路径，旧版本给出明确错误或从权威输入重建。保留来源上传许可、模型预算、提议状态、审核与原文约束。生成器处理自己按当前状态登记的文件。 |
| 5. 当前设计与发布检查 | 文档仍同时说明现行路线和旧版过渡。 | 更新双语设计、使用和验证入口。确认独立 CLI、工作区、只读查询和发布制品的示例可执行。用本次回归证据验证各项能力。 |

TeX 编译兼容性属于现行源输入能力，例如旧文档类、Harvmac 和可审计的 tar 终止记录处理。
有语义差别的命令与读取协议都属于各自的现行能力。每项删除先核对代码调用、字符串入口、
打包声明和现行文档，再为共享逻辑运行受影响测试。历史评审、`Human.md`、权威输入及
用户现有工作区按原有责任边界管理。

## 验收方法

1. 各批通过专项回归后单独提交。全量测试、Ruff、mypy、复杂度与双语文档检查作为最终门槛。
2. 对同一份当前材料比较状态、原包哈希、语法来源、引用候选、结构单元与提议校验。
3. 在新的测试目录复现工作区发布和定点查询。对真实库使用固定 machine 副本与 release。
   若遇到旧 schema，记录具体失败，并对可获得的现行源包另做可比的机械回放。
4. 核对发行包实际安装后的命令和资源。报告无法执行的环境或科学验收项。按完成顺序提交后推送。
