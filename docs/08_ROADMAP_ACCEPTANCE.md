# 08｜Codex 实施阶段与验收规范

## 1. 执行原则与统一阶段编号

`CODEX_TASK.md` 引用本表。P0 固定原型，P1–P5 规定各阶段验收范围；完成状态与证据见
[实施记录](IMPLEMENTATION_LOG.md) 和 [验证报告](../validation/REPORT.md)。
具体命令、环境、断言和结果见[历史报告](../validation/REPORT.md)、[工作区验收](../validation/rfc002/REPORT.md)及各次运行生成的报告。

| 阶段 | 优先顺序 | 交付目标 | 依赖 |
|---|---|---|---|
| P0 | 当前交付门槛 | 固定原型与复现闭环 | 无 |
| P1 | 首要扩展 | 多文档注册表与规范化 Claim 身份 | P0 |
| P2 | 与 P1 紧邻 | 类型验证与 review/apply 事务 | P1 |
| P3 | 按更新成本安排 | 增量重建与 watch | P1、P2 |
| P4 | 按 AI 接入需求安排 | 只读 AI 接口与 MCP | P1、P2 |
| P5 | 按形式化需求安排 | Lean 真实声明／依赖／验证导出 | P1、P2 |

P3、P4、P5 可分别开展；Lean 工作不需要等待 MCP。各阶段保持旧输入可读取，先增加适配器，再讨论废弃旧格式。
类型字段按 [04](04_DATA_FORMATS.md)，维护与发布按 [06](06_MAINTENANCE.md)，Lean 证据按 [05](05_LEAN.md)。

## 2. P0：固定原型与复现闭环

**任务与路径。** 保持 `parser.py → graph.py → store.py → query.py` 的共享流程；补全 splitter 入口、示例、CLI 说明和复现脚本。
`qecgraph split`、`qec-graph split`、`qec-latex-split` 和 Python `split_project` 必须调用同一 ingest 实现，source-only 模式不接收 annotations/catalog。
完整语义补充继续使用 `ingest --annotations/--catalog`，不能给 splitter 偷加自动 QEC 参数推断。

在安装本包及所需依赖后，从包根目录运行：

```bash
python tools/reproduce.py --out build/reproduce
```

该命令应保存可审阅的命令、退出码、stdout/stderr 与检查结果。不能把示例报告或上次运行的数字写成本次实测。
准确依赖、CLI 参数和产物路径按脚本与 [03_SPLITTER.md](user/splitter.md)；测试总数以运行结果为准。

**验收。** 原型语义回归通过，支持的样例完整抽取；三视图、SQLite 和节点片段属于同一快照；来源切片、资源及 manifest 可校验。
仅入口与输出位置不同、其余语义输入相同的运行应产生相同图和 snapshot ID；结果中的绝对路径允许不同。
演示 search、show、deps、impact、context；检查数据上下文包含显式连接的表示或矩阵，并保持证据状态。
重复 ingest 不修改原始输入，且复用相同快照；修改已审核输入后旧审核失效。

**失败例。** 引用被提升为已审核依赖；`leanok` 变成 verified；CRLF 源码切片错误；缺失 include 被报告为完整；候选边绕过 context 最终过滤。
partial 抽取的当前行为必须测试为：生成完整性合格的 partial 快照、更新 CURRENT、CLI 退出 2。
致命构建失败应退出 1 并保留已有 CURRENT；初始化可能留下管理目录。P0 不声称已有严格发布模式或多写者事务。

## 3. P1：多文档注册表与规范化 Claim 身份

**任务与路径。** 建议新增 `qecgraph/registry.py`、`schemas/` 中的版本化领域定义、`migrations/` 中的显式适配器及 `tests/registry/`。
建立 source work、source version、来源出现、规范化 claim 和领域实体的独立身份；记录 ID、revision、content hash、source snapshot 的区别。
多对多来源映射保留假设、记号作用域与出处；自动文本相似匹配只能创建候选，不合并身份。
建立明确 corpus/store 查询范围，跨文档 label 查找需要命名空间；catalog 引用资产采用来源根或受管理 URI。

**验收。** 两个项目可含同一 label 而不串线；同一数学结论的两处原文保持两个来源块，可显式连接一个 claim。
同参但不同表示或构造的码不自动合并；论文新版本新增来源版本并保留历史定位。
适配器读入 `qecgraph.graph.v1`、`qecgraph.annotations.v1` 和旧知识库 `0.1.0`，保留原 ID、原文、证据与未识别字段。
迁移输出到新位置并生成映射和拒绝报告；原数据及原哈希协议保持可查。
跨文档查询返回准确作用域、来源版本和快照；无结果只表示所查范围无匹配。

**失败例。** 以标题或 `[[n,k,d]]` 做唯一键；把 source lemma 原地改造成规范化 claim；导入后把外部资产路径错误解释为本 store 路径。
未知 schema 必须明确拒绝解释或保留为不透明输入，不能套用最新字段含义。

## 4. P2：类型验证与 review/apply 事务

**任务与路径。** 建议新增 `qecgraph/validators/`、`qecgraph/review.py` 与 `tests/review/`；保持结构验证、数学检查和人工决定分离。
实现版本化节点／边 schema、端点类型规则、跨记录约束及按 04 定义的 QEC 验证器接口。
对距离 exact/lower_bound/upper_bound、指标定义和实验条件做结构化筛选；未知值不能默认满足硬条件。
review 创建可审阅的差异和证据绑定；apply 使用输入 revision/hash 条件、写者锁和原子写入，拒绝过期提案。
审核记录包含执行者身份及类别、时间、范围、理由、输入绑定和决定。AI 提案或程序检查不能伪装成人工审核。

**验收。** 相同提案重复 apply 幂等；错误项目、过期 revision 或 hash 不匹配不会覆盖现有人工记录。
审核更新必须重新核对陈述、假设和依赖，不能仅替换 expected hash。
`stale/unbound_review/unresolved` 在提升、遍历、最终边集合和注释输出中一致处理；候选开关不解除失效状态。
状态兼容器正确读取 v1 的 `depends_on_reviewed`，不错误要求旧 `status` 必须等于 reviewed。
资源内容在绑定审核前确定；资产变化能使审核失效，外部资产不可读时不能报告仍有效。
只对经过审核的逻辑依赖子图检查强连通分量，输出待判断的问题；文献互引环合法，不能全图强制 DAG。

可在本阶段加入显式 strict ingest／发布策略：部分抽取允许保留为 staging，但是否更新正式 CURRENT 由明确配置控制。
增加新策略时保留旧默认行为或提供显式迁移，不悄悄改变现有 CLI 退出码含义。

**失败例。** 只有距离上界 12 的记录满足“距离至少 12”；非对易矩阵获得 CSS 有效状态；错误类型的 `proof_of` 被接受为证明目标。
结构 schema 通过不能变成数值验证，检查器成功不能变成 Lean 构建成功；精确条件和失败状态必须独立报告。

## 5. P3：增量重建与 watch

**任务与路径。** 建议新增 `incremental.py`、`watch.py` 与针对变更传播的测试；保存输入、处理器、配置、输出和依赖指纹。
初期允许逐文件复用解析结果，但 macros、include、环境映射或未解析依赖变化时保守回退全量重建。
watch 只调度同一构建流程，处理编辑器临时文件、批量保存和重复事件；不能另建一个更弱的提取器。
执行失败、进程崩溃和并发写入按明确发布协议处理；已发布快照始终完整且不可变。

**验收。** 对同一最终输入，增量与全量重建的语义图、来源、审核状态和查询结果相同；仅操作日志或耗时允许不同。
新增、修改、删除、移动 include 文件及改动资产均有用例；旧审核不会因缓存命中而复活。
语法支持范围不改变时，watch 与显式 ingest 输出一致；事件丢失后可通过全量核对恢复。
已采用 strict 策略时 partial 留在 staging；未采用时沿用退出 2 并发布 partial 的显式约定，报告准确说明结果。

**失败例。** 只看 mtime 导致内容变化漏检；改宏后仅重算定义行；未完成索引已进入 CURRENT；旧 SQLite 与新图混用。
增量收益以真实工作负载记录；正确性门槛通过之前不承诺固定加速比例。

## 6. P4：只读 AI 接口与 MCP

**任务与路径。** 建议新增 `mcp_server.py`、接口契约和协议测试；把 search/show/context/deps/impact 暴露为只读工具。
具体工具名称、输入 schema 和错误结构在接口 ADR 中固定，不能仅在提示词里隐含约定。
工具复用 query 层，固定查询 scope/snapshot，设置节点、深度、文本预算与明确截断信息。
每个引用返回可复核来源；状态与证据类型机器可读，来源内容视为资料而不是执行指令。

**验收。** 相同输入和快照下，CLI、Python 与 MCP 的语义结果相同；不存在 MCP 专属的候选／失效过滤漏洞。
调用搜索与上下文不写人工记录、不执行论文代码、不运行 TeX，也不自动触发 Lean 构建。
预算不足时标出缺失部分，保持完整假设与陈述或明确拒绝把截断内容当完整结论。
测试已知结果、空结果、重复 label、错误 scope、旧 snapshot、截断和 partial 状态。

**失败例。** MCP 展示候选为已确认；任务中无提示地混读两个 CURRENT；检索未命中被表述为定理不存在。
已实现的只读 MCP 入口和验收见 [MCP 指南](12_AI_MCP.md)。

## 7. P5：Lean 真实声明／依赖／验证导出

**任务与路径。** 按 05 建立实际 `lean/` 工程、导出适配器、固定版本的测试 fixture 和构建证据记录。
导出准确 declaration name、完整类型、imports、实际引用常量、信任相关信息、工具链与 mathlib 提交，以及构建命令和日志。
依赖导出记录直接／传递、是否经过过滤及导出器版本；不要把作者 `uses` 当 proof term 的实际常量依赖。
原文与 Lean 类型的对应关系独立审核；编译通过只证明该准确形式化陈述在所用环境下被接受。

**验收。** 固定提交的真实构建产出证据；改变类型、imports 或工具链会使旧证据停止代表新输入。
存在 `sorry`、自定义公理或额外求值信任条件时可观察并按明确策略处理，不填写笼统的“无公理”。
仅名字存在、blueprint `leanok` 或旧构建日志均不能产生当前 verified；类型假设不匹配的文献映射不能自动通过。
有限计算证书需要实际 Lean checker 及输入编码桥接；没有这些时保持 computed/certificate 状态，不能改标 Lean verified。

**失败例。** 构建了另一个提交；仅 `checkdecls` 成功就标证明完成；数值脚本通过被写成 Lean 证据；删掉原文假设仍宣称语义等价。
本阶段不要求一次形式化整个 QEC 体系；先完成一个边界清晰、可重放的结果，再扩展依赖。

## 8. 跨阶段回归与完成定义

[02 的 G01–G12](02_QEC_GRAPH_SPEC.md) 是跨阶段不变量；新增测试针对真实风险，不只重复实现内部流程。
以下失败样例必须能定位到来源、关系或证据层，而不是只返回笼统错误：

| 用例 | 正确结果 |
|---|---|
| 证明提及背景定理但无依赖声明 | 保持引用；推测关系只能是候选 |
| 引用环与审核逻辑依赖环 | 前者保留；后者报告审核问题，不自动删边 |
| 两个已选节点间还有失效或候选边 | 最终 context 仍执行状态过滤 |
| 定义文字或资源文件已变 | 旧绑定失效并保留可审计历史 |
| 距离仅有上界，或下界未知 | 不匹配要求足够下界的查询 |
| claim 有多处原文，或原文含多项 claim | 保留多对多身份及各自假设 |
| 模拟、有限穷举和 Lean 检查结果 | 各自保留证据类别及适用范围 |

阶段完成必须包含：实现与兼容说明、对应回归、实际命令和退出码、输入与工具版本、产物清单、已知限制，以及更新后的能力表。
不能把未运行测试、计划中的接口、缺失资产或未构建 Lean 项目标成通过。
新依赖或上游代码采用按 [07](07_CODEGRAPH_MAPPING.md) 固定版本并检查许可证；变更必须可在干净目录复现。
发布前阅读 `validation/REPORT.md`，确认文档中的当前能力、CLI 行为和失败语义与实测一致。
