## 逐项 reply（实施前）

### A1 — 抽取到 research 的通路

Reply：先通过 A2 暴露全部提及；检查现有 data 输出能否提供 n/k、实体区分和逐字段的逐字证据。不能把只有名称的 code/decoder/noise 字符串自动合并为同一实验。缺乏实体身份、实验绑定及引文的记录保留 proposed 提及。实体归并 skill、六类记录转换和批量人工审核需要可靠的输入/输出样例与人工科学验收；若现有产物不足，将具体缺口和后续验收留给人工，不伪造结构化记录。

### A2 — 四类 proposal 消费

Reply：统一四类 proposal 的机器查询投影，定义独立 kind 和检索文字，默认包含 proposed，支持显式排除和精确 fetch。保留旧 thought ID 算法；human 仍只展示九问。验证四类和来源/状态不变。

### A3 — 正文陈述与 theorem context

Reply：context 可附同一来源和章节范围内的 theorem/assumption 提及，明确 origin、proposed；缺失只说明未抽取，不断言论文不存在假设。D1 增加真实 assumption/notation 类型；不把 proposal 建成 reviewed 证明边。

### A4 — 论文元数据

Reply：将字面 title/author 解析放到 source 公共模块供查询和 renderer 复用；从固定 release 的显式 metadata、来源、AI 提议按优先级构建带来源状态的论文卡片。包名 arXiv 仅作 filename_candidate，不改 work_id，不冒充确认 URL。接入 B6 列表。自动确认身份、外部下载及复杂作者消歧留作人工明确操作。

### A5 — 参考文献与跨论文引用

Reply：先核对 parser 如何保留 bibliography，能可靠划分的 bibitem 保持精确 span；引用键歧义不能任意选第一条。跨论文匹配只允许已确认标识，不能用候选包名建立确定关系。BibTeX 宏/字符串、.bbl 引入路径和跨版本解析需共同设计；无法覆盖的形式明确留给人工，不以全文正则误报为完整书目解析。

### A6 — 多代结构

Reply：workspace 作为新增功能入口；旧 store/corpus/schema/审核语义保留兼容。报告要求删旧接口与当前 AGENTS 的兼容性要求冲突，无法仅凭字段同名完成有损 record→research 迁移。记录逐类型迁移、审核证据保留和退役版本决策，交人工确认；本次不删仍可读取的历史数据或入口。

### A7 — Lean 残留

Reply：保留现有明确 deferred 边界，检查读路径隔离。移动到可选分发会改变 schema、历史记录和 CLI 兼容性，且需要独立打包/安装验收；无 Lean 科学验证条件时不宣称完成迁移，列为人工维护决策。

### B1 — 默认检索

Reply：无向量索引时也使用本地 BM25，统一空白、QEC 词项和 AND 优先/OR 补充，保留 literal 模式；精确过滤先于排名。可选向量保留。SQL 持久化与 C3 的存储迁移统一处理，不额外制造一份权威内容。真实副本记录改前/改后检索数字。

### B2 — 检索单元与命中片段

Reply：默认排除整文件、文档和书目，保留显式 kind 查询；使用阅读文字与论文/章节上下文。按实际匹配词选择原文窗口并返回来源范围，去重重叠来源单元；控制同论文结果占比但保留分页含义。派生文字偏移不得冒充原文坐标。

### B3 — 可选索引失败

Reply：将可选索引构建失败记录为 stale/unavailable，结构发布继续、返回 partial 和可见原因；读路径降级 BM25。未知程序异常仍失败。二进制向量与分片/SQLite 后端需要与 C3 一次迁移，不能只换扩展名或静默忽略损坏。

### B4 — MCP 说明

Reply：集中管理面向 agent 的工具/参数说明，明确用途、返回、proposal 与空结果含义；initialize instructions 给出定位→读取→上下文→精确查询流程。增加描述唯一、参数有说明契约。

### B5 — 返回体

Reply：增加会话固定 release 内的确定性短句柄和 concise/full；fetch/context/trace 接受句柄，保留完整 ID 兼容。concise 搜索省去重复哈希，保留论文/章节、位置、proposal 状态及省略提示。覆盖信息集中 status，source fetch 仍有完整来源。

### B6 — 目录、论文列表和卡片

Reply：outline 按 parser order，默认章节，可显式 blocks；只列来源结构，不列 asset/citation_key。新增 qec_list_papers 与 card，复用 A4；限制卡片内容、明确省略，不拼接重叠块冒充全文。

### B7 — 预算错误

Reply：trace/context 在完整根节点可容纳时缩小深度和节点数，返回 truncated/实际参数；根也放不下才给带 required_chars 和建议的错误。保持返回的原文陈述完整。

### B8 — 默认 profile

Reply：默认改 research，文档和测试同步；显式 legacy/compatible 暂保留以遵守兼容性要求，标注 legacy 为兼容用途。删除 profile/别名留给 A6 迁移决策。

### B9 — 资源 URI

Reply：新资源 URI 绑定源版本和内容，而非 release；仅列论文入口，用模板定位已登记节点。旧 release URI 仍可在其原会话访问；校验 hash、范围与固定版本，禁止任意文件路径。

### B10 — 宏与引用上下文

Reply：从登记源码读取字面宏声明，保留定义原文及定位，只附片段实际用到的定义，不展开、不执行 TeX；附显式 ref 目标摘要。复杂作用域/重定义要标明限制，不能猜语义。

### B11 — 真实评测

Reply：增加离线评测脚本和真实来源定位问题，输出 recall@5/10、MRR、返回字符数和失败；在副本运行前后对照。作者自拟样例只算工程 smoke，50 题科学答案、相关性金标和每 skill 30 条精确率必须人工审核，单独列遗留。

### C1 — 身份与构建字节

Reply：先把 extraction identity 与 build provenance 分开，按 source/config/PARSER_VERSION/RULE_VERSION 定义新语义指纹，工具字节仅记 provenance。保留旧快照读取，不修改历史审核哈希。文件内容定位/自动 rebind 涉及 schema 及审核信任迁移，缺乏逐条等价证明的部分必须人工处理。测试非解析实现变化不换新 identity，解析语义版本变化必须换。

### C2 — 存储与 GC

Reply：先量化当前引用闭包；不能删除被历史 release、paper_version 或审核引用的快照，也不能让 machine 查询依赖外部 sources（违反严格挂载隔离）。安全缩减需要新快照格式/迁移及保留策略。无完整引用证明不执行删除，记录人工的保留 release/历史审核策略和空间验收条件。

### C3 — 单体 state 与全量校验

Reply：不可仅信 manifest 来跳过仍可被外部修改的文件。state 分片、增量闭包校验、只读 SQLite 必须与 C2/C8 迁移和损坏检测一起设计。先落实 C8 可验证格式；未有可证明安全的增量算法、历史读取与恢复迁移前保留完整验证，记录人工架构遗留及 500 篇验收要求。

### C4 — 读路径重复工作

Reply：缓存固定会话内的邻接表与可复用排名统计；检查哪些重复校验可安全移到读取目标时。不得删除现有防篡改测试来换速度。启动全库加载及全树检查的彻底去除依赖 C3 的按对象完整性边界；必要部分保留并解释。

### C5 — AI 持锁与发布阶段

Reply：结构与 AI 两次发布需要重新规定 claim 的消费条件、fallback 解析、并发源变更以及恢复日志。不能简单释放锁后继续用旧 candidate 覆盖新 release。先检查现有恢复测试；无完整 CAS/rebase 协议时列为人工架构项，明确阶段状态和冲突案例，不用删锁冒充修复。

### C6 — 配置指纹

Reply：每个 material 只绑定自身解析输入/limits/source override 和语义版本；排除 API key、模型、并行度、检索配置、别的论文和 Python 构建文本。source metadata 更新仍需正确登记，不能因缓存忽略。验证密钥轮换/无关配置不重解析。

### C7 — 审核发布与身份

Reply：AI 决策应通过 registry 锁注册 hash-bound 索引并发布 release；读取以固定 state 为准，旧文件不自动冒充已登记决定。TTY 只能证明交互环境，不能认证人类，uid 同样不能防 agent 冒用；真正的人类签名/密钥隔离需要用户建立信任根。保留“本地声明”的明确限制，不伪造 human 身份。

### C8 — state schema

Reply：新增版本化 state schema，校验注册表顶层及 material/索引形状；旧无版本数据先校验旧结构再显式适配，hash 校验始终针对原始内容。拒绝未知版本，错误指向 state 路径。测试 hash 合法但字段非法的数据和旧 release 读取。

### D1 — 环境类型

Reply：扩充 abstract/algorithm/assumption/claim/notation/acknowledgments，未知 theorem 保留 statement_other 与 heading；同步图 schema、视图和 context，提升 PARSER_VERSION，测试精确 source span。title/author 与 bibliography 分别由 A4/A5 配套。

### D2 — 码记法

Reply：增加带原文偏移映射的记法规范化，支持 llbracket、紧缩括号及 TeX 空格；保存原 notation，不推断距离真实性；提升 RULE_VERSION，测试范围和三种写法。

### D4 — 非 UTF-8

Reply：原始字节继续归档，不用 latin-1 必然可解码这一事实猜编码。检查 inputenc 声明及所有 hash/坐标读取方；未有贯通 encoding schema/normalized source mapping 的安全迁移前，至少让入口/解析诊断明确编码问题。完整回退要覆盖读取、校验、AI 和 MCP，不能只在 parser 解码而破坏证据。

### E1 — AI 输入与缓存

### E2 — 长论文分块

### E3 — 上传与批次预算
