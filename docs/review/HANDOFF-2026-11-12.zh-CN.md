# 2026-11-12 人工遗留交接

本文件记录本轮无法安全闭合的设计、迁移和科学验收问题。它不是已实现功能声明。逐项原计划和实际结果见 [REPLY](REPLY-2026-11-12.zh-CN.md)。

## A1 — 实体归并与 research 转换

机器副本固定 release `aabc5ef397e0300bc085ea687c8beb2a12ea82080f7d0536cd609f661ff5fa22` 有 518 条 data 提议，字段仅 code/conditions/confidence/decoder/metric/noise_model/source_refs/unit/value；没有独立 n/k、source_quote 或实验 ID。有效 research 只有五个 paper_version 和一个 code_parameters_mention。名称字符串不足以确认不同实验使用相同码、噪声通道或译码器配置。

已通过 A2 让全部提议可检索、读取。未建立未经验证的实体合并或记录提升。需人工先标注至少两篇多实验论文的实体边界、逐字段引文和 unknown，确定同名实体的版本/呈现规则；再实现独立版本化 resolver，输出 proposed research bundle，经现有 validate_bundle/validate_sources 后由人工导入。验收必须包括同名不同配置、缺少 n/k、冲突数值、表格列条件及不同 metric denominator；不允许把缺失当作不存在。

## A6 — 兼容接口的迁移与退役

当前 AGENTS 要求保持 CLI 兼容、破坏性变化提供迁移。legacy record 的 review_binding、Lean provenance 与 research field_evidence 不存在已批准的一对一无损转换。仅按 kind 改名会丢失审核有效性。

本轮 workspace 新增功能统一使用 research；CLI 默认 research，store/corpus 和显式 legacy/compatible 继续可用。维护者需批准退役版本和保留期限，建立 record-kind → research-kind/只读历史 的转换表，并分别处理证据闭包、未知枚举和旧 source locator。迁移验收：旧库固定查询可重放，导出内容/哈希不变，双版本读取，失败不动 CURRENT；之后才删除入口和重复 schema。

## A7 — Lean 可选分发边界

设计明确 Lean deferred，但历史记录的类型、审核和 CLI 仍读取其 provenance；移动文件会改变 wheel、单文件可执行程序和历史导入路径。现有架构检查约束读取端不执行 Lean，本次没有运行 lake/Lean，不能把打包调整称为科学验证。

维护者需决定 extras、独立包或彻底退役，并指定可重放的历史 Lean 记录样例及支持矩阵。验收应分别安装核心与可选包：核心 query/MCP 不加载或执行 Lean；旧记录仍能只读显示 unsupported/deferred；可选包明确 toolchain/mathlib/传递公理审计。不得删除历史证据来简化分发。

## C2 — 紧凑快照与垃圾回收

本轮只读副本实测 machine 为 88,334,613 字节、8,217 文件、22 个 snapshot manifest、5 个当前源版本。报告的历史 paper_version 修订会继续引用旧快照。没有删除任何原库或副本中的证据。C1 已减少未来因无关代码变化而产生的新快照，但不缩减历史体积。

报告建议让 machine 读取外部 sources，与严格仅挂载 machine 的边界冲突。应先设计 machine 内来源 CAS 与紧凑 snapshot v3，并保留旧 store 的 views/SQLite 兼容导出。维护者必须决定保留哪些 release、审核和 proposal；GC 以它们为根遍历完整引用闭包，默认 dry-run，再原子隔离待删对象，恢复测试通过后删除。验收需包含旧 release 复读、历史审核、损坏链接/被替换文件、GC 中断恢复和重建一致；5 篇 <15 MB/<300 文件目标尚未达到。

## C3 — 分片 state、增量校验与库级 SQLite

已落地 C8 的版本化 state 校验；仍保留全库来源验证。内容寻址文件可被外部进程原地改写，manifest 本身未变不能证明 graph/SQLite/原文未变；直接跳过验证会回归现有篡改检测。

后续需先规定受信不可变存储或逐对象读时核验边界，再设计根 state→work shard→record/source 闭包的 v2 格式及只读 SQLite 投影。同步定义旧 release 读取、分片迁移失败恢复和 deep validation；索引不得成为可编辑权威。C2 的来源 CAS、B3 的二进制/分片向量及 C4 的惰性加载共用该迁移。验收至少 500 篇增量导入与 cold/warm 查询，报告新增成本、内存、损坏检测及固定会话结果；本轮没有跑 500 篇压测。

## C5 — 结构发布与 AI 发布分离

现有 AI 网络工作仍在 writer 锁内；没有简单解除锁。原因是 AI normalization/structure recovery 本身决定有效 source snapshot，旧 candidate 不能在无锁期间覆盖新的 review、record 或来源版本；现有 claim 消费承诺也依赖统一发布阶段。

需要维护者确认事务语义：结构阶段只发布可验证的本地解析，无法本地解析的材料保持 pending；AI 任务读固定 source_version/snapshot/配置，锁外写 staging；重新取锁以该 tuple 做 CAS，只合并本论文 proposal，不覆盖无关 state。源或配置变化则标 stale job 并重排；决定审查、崩溃、中断、重复提交和输入恢复必须有专门故障测试。何时消费依赖 AI 归一化的输入需要明确政策。E3 已提供默认离线和批次限额，但不等于完成两阶段发布。

## E2 — 长文切片与全局合并

当前完整请求超过 max_input_chars 仍明确失败，未截断原文或伪报抽取完成。v6 减少逐行 JSON 转义，但不消除长文预算限制。

需设计带原 file/全局行号的 overlapping evidence windows，固定 skill/chunk/模型身份和失败恢复；每个提议保留引用所属窗口与跨窗口未满足前提。theorem 标签去重不能任意选第一条，thoughts 的全文结论需单独有证据的合并步骤，空窗口不能产生全局 absence。维护者应提供 >预算的真实多文件论文及人工分段金标，验证窗口边界公式、跨节假设、重复引文和冲突结论。临时处理可提高明确预算或由人工审核导入；不建议拆包伪装成不同论文身份。
