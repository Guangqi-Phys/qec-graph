# 知识库的运行与维护

本文件规定起步阶段的维护方式。这里描述的是建议架构；模板没有部署数据库、下载容器镜像或启动服务。

## 1. 保存权威记录，按需生成索引

采用三类存储：Git 保存结构化知识、说明文字、Schema、脚本和 Lean 源码；持久资产目录保存论文、矩阵、实验数据与证书；索引目录保存由前两者生成的查询投影。

| 内容 | 权威位置 | 修改方式 |
|---|---|---|
| 代码参数、定理假设、证据关系 | 对应 JSON/YAML 记录 | 修改记录并提交 Git |
| 证明实现 | Lean 源文件 | 修改源码并重新构建 |
| 论文某个版本 | 原始资产及其清单 | 新版新增文件，保留旧版 |
| 人工修正的公式与注释 | 经整理的记录 | 保留修改历史和原文定位 |
| 全文、向量、查询表 | 派生索引 | 从权威记录重新生成 |

一项字段只设一个权威源。例如，代码实例的 n、k 写在实例记录中，说明页和 SQL 表均由它生成。若使用 Zotero 管理标题、作者和书目，导入器只能更新约定的书目字段，不能覆盖人工整理的定理或参数。避免两个系统同时独立编辑同一字段。

资产使用 SHA-256 校验，并在清单中记录类型、长度、来源版本和相对位置。对象 ID 表示身份，哈希表示具体内容；重命名文件不应改变对象身份。自动抽取文本可以重建，人工校正和成本较高的抽取输出应持久保存。

## 2. 本地查询与升级条件

第一版用 SQLite 保存查询表和 FTS5 索引。SQLite 适合本地应用，同一时刻只有一个写者；多人通过网络直接访问同一个数据库文件也不是推荐用法。[1] 索引构建统一由一个进程执行，普通查询只读。

当出现持续的并发写入、需要多台服务共同访问、集中权限管理或远程事务接口时，再评估 PostgreSQL。论文数量本身不是迁移阈值。迁移时明确数据库是继续充当投影，还是接管某些字段的权威来源；后一种选择必须停止这些字段的文件双向编辑。

FTS5 提供 BM25 等全文能力，但默认分词规则不能直接承担中文词法理解。[2] 保留原文，同时生成经过分词的搜索文本；维护中英术语、缩写和符号别名。数学公式保留 LaTeX，并记录相关定义 ID，不假设字符串相似意味着数学等价。

参数范围、构造类型和证据等级先用结构化查询过滤。语义检索用于寻找相关讨论，返回答案前仍要校验硬条件。未来使用 pgvector 时，需注意近似索引可能遗漏候选；官方支持将其与 PostgreSQL 全文搜索结合。[3]

## 3. 按需使用容器

起步可用 Docker Compose 描述两个按需任务：research 负责抽取、验证和索引；lean 负责形式化构建。采用 GROBID 等独立解析服务时，再加入 parser。任务结束即可退出，无须预先建立长期运行的微服务。

| 挂载内容 | 建议方式 |
|---|---|
| 原始论文与已发布资产 | 只读挂载 |
| 经整理记录 | 查询和验证时只读；编辑任务使用独立工作目录 |
| 新产物与验证报告 | 写入明确的持久输出目录 |
| 构建缓存、索引 | 使用可重建的独立目录或 volume |
| 临时文件 | 放入可清理工作目录 |

源码需要宿主机编辑时使用 bind mount；数据库服务的数据目录可使用持久 volume。Docker 可写层随容器销毁而消失，volume 的生命周期独立于容器。[4] 运行环境和长期数据因此要分别管理。

镜像选定后记录实际 digest，依赖使用实际生成的锁文件。Python 依赖、系统库、Lean toolchain、Lake manifest 和 mathlib 修订都应明确；模板不填写未经核实的 digest。硬件、平台和并行设置会影响实验复现时，也要进入运行记录。

## 4. 增量更新与失效规则

每个生成任务记录输入哈希、处理器版本、配置哈希、Schema 版本和输出哈希。embedding 另记模型修订、维度、归一化方法及输入文本哈希。更换模型后生成独立索引，不能混合不同向量空间。

新增论文版本时，新增资产与来源记录，比较旧版涉及的定义、参数和定理，把受影响对象标记为待复核。引用继续定位原先版本，不因“最新版”出现而自动改写。分块算法变化只重建检索片段；永久证据定位使用论文版本、章节、页码或 LaTeX 标签。

依赖发生变化时，重算直接受影响产物，再沿记录中的依赖关系传播。新索引在临时位置完整构建、校验后切换，失败时继续使用旧索引并显示其版本。不要让半更新的查询表与另一版本的全文索引共同对外提供结果。

## 5. Schema 迁移和数据审核

记录包含 schema_version。变更字段含义时提供迁移脚本和迁移说明，在副本中执行；检查必填项、枚举、引用完整性及关键查询，再提交结果。缺失值用 null 或明确的 unknown 状态，不能用 0 代替未知距离或失败次数。

人工审核确认来源与语义，自动校验负责结构和已定义的计算条件。两者分别记录状态；格式验证通过不能被解释成定理正确或计算结果已经形式化证明。

## 6. 备份、恢复与快照

备份至少覆盖 Git 历史、原始资产、重要计算产物、人工修订以及资产清单。Git 远端不会自动保存未追踪的大文件。每个发布快照记录 Git commit、Schema 版本、资产清单和验证报告。

定期在空目录恢复一次：核对文件哈希，重建查询索引，运行代表性的参数查询、引用定位和 Lean 构建。恢复演练比只确认备份命令成功更能说明资料可用。

SQLite 若仅保存派生索引，可直接重建；若以后存有独有数据，运行中的数据库应通过一致性快照或官方 Backup API 保存。[5] 大批实验结果可持久保存为 Parquet，由 DuckDB 直接查询，减少重复数据副本。[6]
